# **二、总体设计**

## 2.1 基本设计描述

勤工助学岗位匹配管理系统是面向高等院校的勤工助学信息化管理平台，旨在解决传统人工管理模式下岗位信息分散、供需匹配效率低、审核流程繁琐等问题。系统采用 **"微信小程序 + Vue 网页端 + Flask 后端"** 三端协同架构，实现勤工助学全流程的数字化管理。

**使用人群**：

- **学生用户**：通过微信小程序或网页端浏览岗位、提交申请、查看审核结果和薪资明细。系统根据学生的专业、年级、成绩和空闲时间，利用四维度加权匹配算法为学生推荐合适的岗位。
- **管理员用户**：通过管理后台发布和管理岗位、审核学生申请、录入和发放薪资、发布公告通知、导出统计报表。

**核心功能**：

系统包含 **用户管理、岗位管理、智能匹配、申请审核、薪酬管理、数据统计、系统设置** 七大功能模块。用户管理支持注册、登录、个人信息维护和权限控制；岗位管理支持岗位的发布、编辑、上下架和多维度筛选；智能匹配模块基于专业（30%）、年级（20%）、成绩（25%）、时间（25%）四维度加权算法计算匹配度；申请审核模块实现申请提交、审核通过/驳回、结果通知的完整流程；薪酬管理支持工时录入、薪资计算和批量发放；数据统计模块提供岗位、学生、申请、薪资等多维度统计分析；系统设置模块支持公告发布和数据导出。

**业务规则说明**：

1. 学生点击"申请"按钮后，系统检查该学生是否已对同一岗位提交过待审核或已通过的申请，若有则提示"您已申请过该岗位"，不允许重复提交；若之前申请被驳回，则允许重新申请。
2. 提交时系统自动冻结学生当前的个人信息（专业、年级、学院、家庭类型等）快照存入 `studentInfo` 字段，后续学生修改个人信息不影响已提交的申请记录。
3. 岗位状态为"已满员"或"已关闭"时，不允许提交申请。

**业务规则说明**：

1. 管理员只能审核处于"待审核（pending）"状态的申请，已处理的申请不能重复审核。
2. 驳回操作强制要求填写驳回理由，确保学生能了解被驳回的原因。
3. 审核完成后系统自动记录审核人姓名和审核时间。
4. 管理员可通过"查看学生"按钮跳转到学生管理页面，查看该学生的详细信息；通过"查看岗位"按钮跳转到岗位管理页面，查看岗位详情。

# **三、数据结构**

## 3.1 数据库表列表

| **表名** | **作用** |

## 3.7 ER 图描述

**实体关系说明**：

```
┌──────────┐         ┌──────────────┐         ┌──────────┐
│          │  1 : N  │              │  N : 1  │          │
│  users   │────────→│ applications │◄────────│   jobs   │
│  用户表   │         │   申请表     │         │  岗位表   │
│          │         │              │         │          │
└────┬─────┘         └──────────────┘         └────┬─────┘
     │                                              │
     │ 1 : N                                        │ 1 : N
     ▼                                              ▼
┌──────────────┐                            ┌──────────────┐
│              │                            │              │
│salary_records│                            │  notices     │
│   薪资表     │                            │   公告表     │
│              │                            │(无外键关联，  │
└──────────────┘                            │ 由管理员发布)│
                                            └──────────────┘
```

**关联关系详解**：

1. **users → applications（一对多）**：一个学生可以提交多条岗位申请。通过 `applications.studentId` 关联 `users.studentId`。申请提交时将学生信息快照存入 `studentInfo` 子文档，保证数据独立性。

2. **jobs → applications（一对多）**：一个岗位可以收到多条申请。通过 `applications.jobId` 关联 `jobs._id`。

3. **users → salary_records（一对多）**：一个学生可以有多条薪资记录。通过 `salary_records.studentId` 关联 `users.studentId`。

4. **jobs → salary_records（一对多）**：一个岗位可以产生多条薪资记录。通过 `salary_records.jobId` 关联 `jobs._id`。

5. **notices（独立实体）**：公告表不与其他表建立外键关联，由管理员直接发布和管理，所有用户均可查看。

6. **申请状态流转**：`pending`（待审核）→ `approved`（已通过）/ `rejected`（已驳回）；`pending` → `cancelled`（学生取消）；`rejected` → `pending`（重新申请）。

7. **薪资计算规则**：`amount = workHours × hourlyRate`，由管理员录入工时后系统自动计算金额。

### 代码一：智能匹配算法（Python 后端 — helpers.py）

```python
def calculate_match_score(user_info, job_info):
    """
    计算岗位匹配度

    Args:
        user_info: 用户信息字典
        job_info: 岗位信息字典

    Returns:
        匹配度分数 (0-100)
    """
    score = 0

    # 专业匹配 (30%)
    if job_info.get('requiredMajor'):
        if user_info.get('major') == job_info['requiredMajor']:
            score += 30
    else:
        score += 30  # 无专业要求，默认满分

    # 年级匹配 (20%)
    if job_info.get('requiredGrade'):
        if user_info.get('grade') == job_info['requiredGrade']:
            score += 20
    else:
        score += 20  # 无年级要求，默认满分

    # 成绩匹配 (25%)
    if job_info.get('minGpa'):
        user_gpa = user_info.get('gpa', 0)
        if user_gpa >= job_info['minGpa']:
            score += 25
        else:
            # 线性计算部分分数
            score += int(25 * (user_gpa / job_info['minGpa']))
    else:
        score += 25  # 无GPA要求，默认满分

    # 时间匹配 (25%) - 简化处理
    score += 25

    return min(score, 100)
```

**算法说明**：四个维度独立评分后求和，上限100分。若岗位对某维度无要求（如不限专业），该维度自动满分。GPA 维度采用线性插值，未达最低要求时按比例给分。

async function submitApplication(event) {
  try {
    const userInfo = await verifyUser(event)
    if (!userInfo || userInfo.role !== 'student') {
      return unauthorized('请先以学生身份登录')
    }

    const { jobId, phone, email, availableTime, experience, reason } = event

    if (!jobId || !reason) {
      return badRequest('岗位ID和申请理由为必填项')
    }

    // 验证输入
    if (!isValidLength(reason, 500)) {
      return badRequest('申请理由不能超过500字')
    }
    if (phone && !isValidPhone(phone)) {
      return badRequest('手机号格式不正确')
    }

    // 检查岗位是否存在且正在招聘
    const jobResult = await db.collection('jobs').doc(jobId).get()
    if (!jobResult.data) return error(404, '岗位不存在')
    if (jobResult.data.status !== 'recruiting') {
      return error(400, '该岗位已停止招聘')
    }

    // 防止重复申请（仅检查pending和approved状态）
    const existResult = await db.collection('applications').where({
      studentId: userInfo.studentId,
      jobId: jobId,
      status: _.in(['pending', 'approved'])
    }).get()

    if (existResult.data.length > 0) {
      return error(400, '您已经申请过该岗位（待审核或已通过）')
    }

    // 写入申请记录（冻结学生信息快照）
    const now = db.serverDate()
    const result = await db.collection('applications').add({
      data: {
        studentId: userInfo.studentId,
        studentName: userInfo.name,
        studentInfo: {
          major: userInfo.major, grade: userInfo.grade,
          college: userInfo.college, gender: userInfo.gender,

### 代码三：管理员审核申请（云函数 — applications/index.js）

async function reviewApplication(event) {
  try {
    const userInfo = await verifyUser(event)
    if (!userInfo || !verifyAdmin(userInfo)) {
      return unauthorized('需要管理员权限')
    }

    const { applyId, rejectReason = '' } = event
    const reviewAction = event.reviewAction || event.action

    if (!applyId || !reviewAction || reviewAction === 'review') {
      return badRequest('申请ID和操作不能为空')
    }

    // 获取申请记录
    const appResult = await db.collection('applications').doc(applyId).get()
    if (!appResult.data) return error(404, '申请记录不存在')

    // 防止重复审核
    if (appResult.data.status !== 'pending') {
      return error(400, '该申请已被处理，不能重复审核')
    }

    // 驳回时必须填写理由
    if (reviewAction === 'reject' && (!rejectReason || !rejectReason.trim())) {
      return badRequest('驳回时必须填写驳回理由')
    }

    // 更新申请状态
    const now = db.serverDate()
    const updateData = {
      status: reviewAction === 'approve' ? 'approved' : 'rejected',
      statusText: reviewAction === 'approve' ? '已通过' : '已驳回',
      reviewTime: now,
      reviewer: userInfo.name
    }
    if (reviewAction === 'reject') {
      updateData.rejectReason = rejectReason
    }

    await db.collection('applications').doc(applyId).update({ data: updateData })
    return success(null, reviewAction === 'approve' ? '审核通过' : '已驳回')
  } catch (err) {
    return error(500, '审核失败')
  }
}

// Axios 实例：30秒缓存 + 请求去重 + Token 自动注入
const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 15000,
  headers: { 'Content-Type': 'application/json' }
})

// 请求拦截：Token 注入 + 缓存命中短路
request.interceptors.request.use((config) => {
  const userStore = useUserStore()
  const isPublicApi = PUBLIC_APIS.some(api =>
    url === api || url.endsWith(api))

  if (userStore.token && !isPublicApi) {
    config.headers.Authorization = `Bearer ${userStore.token}`
  }

  // GET 请求缓存检查
  if (config.method?.toLowerCase() === 'get') {
    const cached = getCached(getCacheKey(config))
    if (cached !== null) {
      config.adapter = () => Promise.resolve({
        data: cached, status: 200, statusText: 'OK',
        headers: {}, config
      })
    }
  }
  return config
})

// 响应拦截：401 自动登出 + 缓存写入
request.interceptors.response.use((response) => {
  const res = response.data as ApiResponse
  if (res.code !== 200) {
    if (res.code === 401) {
      useUserStore().logout()
      router.push({ name: 'Login' })
    }
    return Promise.reject(new Error(res.message))
  }
  return response
})

## 5.1 测试方法

- 黑盒测试，它是通过测试来检测每个功能是否都能正常使用。在测试中，把程序看作一个不能打开的黑盒子，在完全不考虑程序内部结构和内部特性的情况下，在程序接口进行测试，它只检查程序功能是否按照需求规格说明书的规定正常使用，程序是否能适当地接收输入数据而产生正确的输出信息。黑盒测试着眼于程序外部结构，不考虑内部逻辑结构，主要针对界面和功能进行测试。
- 黑盒测试是以用户的角度，从输入数据与输出数据的对应关系出发进行测试的。

### 系统整体运行情况

1. **核心业务流程运行正常**：学生注册→登录→浏览岗位→提交申请→管理员审核→薪资发放的完整流程在小程序端和网页端均能顺畅运行，数据在三端之间实时同步。
2. **智能匹配算法工作正常**：四维度加权匹配算法能正确计算专业、年级、成绩的匹配分数，未设置限制条件的维度自动满分，匹配度上限正确控制在100分。
3. **安全机制有效**：密码加密存储、JWT Token 认证、角色权限控制、输入验证、SQL注入防护、XSS防护等安全措施均经过验证，能有效阻止非法访问和恶意输入。
4. **异常处理完善**：重复申请拦截、重复审核拦截、驳回必填理由、已发放薪资不可编辑等业务规则均正确执行，异常情况有友好的中文提示。

### 发现的问题与优化建议

1. **时间匹配算法待完善**：当前时间匹配维度为简化处理（默认满分25分），建议后续根据学生空闲时间段与岗位工作时间段的重叠度进行精确计算。
2. **云数据库查询限制**：微信云数据库 HTTP API 单次查询上限为20条记录，当前通过设置较大 limit 值缓解，数据量增长后可能需要引入游标分页机制。
3. **Excel 报表导出**：当前数据导出为 JSON 和 CSV 格式，建议后续引入 SheetJS 库支持 Excel（.xlsx）格式导出，以满足学校行政管理的格式要求。
4. **消息通知功能**：建议后续增加微信订阅消息推送，在申请审核结果、薪资发放、新岗位发布等场景主动通知用户。
5. **系统日志功能**：system_logs 集合已创建但缺少查询接口和管理界面，建议补充日志查看功能以便运维排查。
