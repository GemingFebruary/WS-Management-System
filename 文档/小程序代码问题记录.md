## 待修改问题列表

### 1. 【重要】云函数需要添加HTTP调用逻辑以支持Python后端

**问题描述**: 当前小程序直接使用微信云开发的云函数和云数据库，需要修改为支持调用Python后端API。

**影响范围**: 所有云函数 (auth, jobs, applications, salary, admin)

**修改建议**:

在每个云函数中添加HTTP请求逻辑，优先调用Python后端，失败时回退到本地云开发：

```javascript
// cloudfunctions/auth/index.js
const axios = require('axios');

// Python后端API地址
const API_BASE_URL = 'http://your-server-ip:5000/api';

exports.main = async (event, context) => {
  const { action, data } = event;
  
  try {
    // 尝试调用Python后端
    const response = await callPythonBackend(action, data);
    return response;
  } catch (error) {
    console.log('Python后端调用失败，回退到云开发:', error);
    // 回退到原有云开发逻辑
    return fallbackToCloudDevelopment(action, data);
  }
};

async function callPythonBackend(action, data) {
  const url = `${API_BASE_URL}/auth/${action}`;
  const response = await axios.post(url, data);
  return response.data;
}
```

**优先级**: 高

### 3. 【建议】添加API健康检查

**问题描述**: 小程序启动时无法知道后端服务是否可用。

**影响范围**: app.js

**修改建议**:

在app.js的onLaunch中添加健康检查：

```javascript
// app.js
App({
  onLaunch() {
    // 检查后端服务状态
    this.checkBackendHealth();
  },
  
  async checkBackendHealth() {
    try {
      const res = await wx.request({
        url: 'http://your-server-ip:5000/health',
        method: 'GET',
        timeout: 5000
      });
      if (res.data.code === 200) {
        console.log('后端服务正常');
        this.globalData.backendOnline = true;
      }
    } catch (error) {
      console.log('后端服务离线，使用云开发模式');
      this.globalData.backendOnline = false;
    }
  }
});
```

**优先级**: 低

## 对接方案建议

### 方案一: 云函数代理模式（推荐）

小程序云函数作为代理层，调用Python后端API：

```
小程序页面 → 云函数 → Python后端 → MongoDB
                    ↓
              失败时回退到
                    ↓
              微信云开发
```

**优点**:
- 对小程序页面改动最小
- 可以灵活切换数据源
- 保留云开发的离线能力

**缺点**:
- 增加一层调用延迟
- 需要维护两套逻辑

### 方案二: 直接HTTP调用模式

小程序直接调用Python后端API：

```
小程序页面 → Python后端 → MongoDB
```

**优点**:
- 调用链路最短
- 代码更简洁

**缺点**:
- 需要修改所有页面的调用方式
- 需要处理跨域和域名配置
- 失去云开发的离线能力

---

## 实施步骤建议

1. **第一阶段**: 在Python后端完善所有API接口
2. **第二阶段**: 在云函数中添加代理逻辑，支持双模式运行
3. **第三阶段**: 测试三端数据互通
4. **第四阶段**: 逐步切换到Python后端为主的数据源

---

## 注意事项

1. **数据一致性**: 确保三端对同一数据的读写结果一致
2. **并发处理**: 注意多用户同时操作时的数据冲突
3. **安全性**: 所有API调用都需要进行身份验证
4. **错误处理**: 完善的错误处理和降级机制
5. **日志记录**: 记录关键操作便于问题排查

### 8. 【紧急】首页轮播图图片404错误

**问题描述**: `app.js` 中 `globalData.bannerList` 使用了不存在的占位URL `https://example.com/banner1.jpg` 等，导致首页轮播图全部加载失败，控制台报404错误。

**报错信息**:
```
[渲染层网络层错误] Failed to load image `https://example.com/banner1.jpg`
the server responded with a status of 404 (HTTP/1.1 404)
```

**影响文件**: `app.js` 第38-54行

**修改方案**: 将 `bannerList` 中的图片URL替换为有效的占位图或本地图片路径。

**方案A - 使用本地图片（推荐）**:
```javascript
// app.js - globalData.bannerList
bannerList: [
  {
    id: 1,
    imageUrl: '/images/banner1.png',
    title: '勤工助学，助力成长'
  },
  {
    id: 2,
    imageUrl: '/images/banner2.png',
    title: '丰富岗位任你选'
  },
  {
    id: 3,
    imageUrl: '/images/banner3.png',
    title: '智能匹配，快速上岗'
  }
]
```
> 注意：需在 `images/` 目录下放置对应的 banner1.png、banner2.png、banner3.png 图片文件。

**方案B - 使用在线占位图**:

### 9. 【建议】忽略QGPY目录避免微信开发者工具警告

**问题描述**: 微信开发者工具检测到项目目录下存在 `QGPY/__pycache__` 目录，触发保留目录警告。

**报错信息**:
```
[] 以 '__' 为开头和结尾的目录为保留目录；donutAuthorize__ 是保留目录。
QGPY\__pycache__ 目录下的所有文件将会被忽略。
```

**影响文件**: `project.config.json`

**修改方案**: 在 `packOptions.ignore` 中添加 QGPY 目录忽略规则：
```json
"packOptions": {
  "ignore": [
    {
      "type": "folder",
      "value": "QGPY"
    }
  ],
  "include": []
}
```

**优先级**: 中
